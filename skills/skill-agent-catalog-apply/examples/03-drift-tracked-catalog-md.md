# Example 03 — Drift detection: generated catalog markdown is git-tracked

## Input prompt

> Check whether the catalog wiring in this repo is still in sync with the spec.

## Input files

Repository state at invocation — catalog was wired up months ago, but somebody committed the generated output back into the tree:

```

.
├── .claude-plugin/
│   └── plugin.json
├── skills/
│   ├── foo-skill/SKILL.md
│   └── bar-skill/SKILL.md
├── agents/
│   └── alpha-agent.md
├── docs/
│   ├── catalog-sources.yml
│   ├── requirements.txt
│   ├── skills/                   # tracked in git (drift)
│   │   ├── SUMMARY.md
│   │   ├── foo-skill.md
│   │   └── bar-skill.md
│   ├── agents/                   # tracked in git (drift)
```

`mkdocs.yml` already declares both plugins correctly:

```yaml
  - search

      scripts:
        - scripts/docs/gen_catalog.py

      nav_file: SUMMARY.md
```


`.gitignore` does **not** mention `/docs/skills/`, `/docs/agents/`, or `/docs/tags.md`.

`git ls-files docs/skills/ docs/agents/ docs/tags.md` returns 6 hits.

Working tree is otherwise clean.

## Expected behaviour

1. **Preconditions** — confirm git repo; detect **plugin mode**; locate the spec; report the detected mode.
2. **Audit** — most rows are `pass`, but two are `drift`:
   - `gen-files` plugin → pass
   - `literate-nav` plugin → pass
   - source-roots config → pass
   - source-roots match plugin mode → pass (local plugin is first)
   - Skills/Agents nav via `SUMMARY.md` → pass
   - tag index → pass
   - **generated markdown uncommitted → drift** (evidence: `git ls-files` lists `docs/skills/`, `docs/agents/`, `docs/tags.md`)
   - `task docs` regenerates → pass
   - docs deps include both plugins → pass
   - **`.gitignore` covers generated paths → drift** (none of `/docs/skills/`, `/docs/agents/`, `/docs/tags.md` is ignored, so a future build will re-stage them)
3. **Propose changes** — two per-item approvals, each citing `spec/claude/skill-agent-catalog/en.md` §"Generated markdown stays uncommitted":
   - **Untrack the generated paths.** Run `git rm --cached -r docs/skills/ docs/agents/ docs/tags.md` (note: `--cached` removes them from the index but **leaves the files on disk** so the next `mkdocs build` regenerates them in place). Show the exact command and the count of files that would be removed before executing.
   - **Patch `.gitignore`** to append:

     ```

     # Generated by scripts/docs/gen_catalog.py — do not commit
     /docs/skills/
     /docs/agents/
     /docs/tags.md

     ```

     Place the block at the end of the file; do not reorder existing entries.
4. **Verify** — after applying both changes, run `task docs` and confirm:
   - build pass
   - `site/skills/`, `site/agents/`, `site/tags/` rendered as before
   - `git status` shows the untracked-and-then-ignored deletions staged for commit, but **no** new entries under `docs/skills/`, `docs/agents/`, or `docs/tags.md` (those are now ignored)
   - prompt the user to commit the cleanup (`git rm --cached` deletions + `.gitignore` patch) as a single commit; do not commit autonomously
5. **Hard-rule compliance** — never modify the generator hook, the source-roots file, or `mkdocs.yml` (none of those is in drift); per-item approval is mandatory before either the `git rm --cached` or the `.gitignore` patch runs; cite the spec section in every drift row of the report.
6. **Language** — the user wrote English; conversational output is English, file contents are English.
