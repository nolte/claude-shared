# Audit checklist

The full Acceptance-Criteria checklist for step 1 of `skill-agent-catalog-apply`. Read each spec-item row, classify it as `pass`, `missing`, or `drift`, and gather the evidence. The audit is read-only. Report findings grouped by spec section: Navigation, Generation mechanism, Source roots, Use-case metadata, Per-language summary, Dependencies, Git hygiene.

| Spec item | How to check |
|---|---|
| A catalog generator surface is wired | The spec defines **three** surfaces, all delegating to one generator core (spec §Generation mechanism). Check `mkdocs.yml` for any one of: an `on_pre_build` hook under `hooks:` (the **recommended default**); a standalone pre-build step (a `Taskfile.yml` `docs` target or the module's `__main__` invoked before `mkdocs build`); or a `gen-files` entry under `plugins:`. **Any** of the three is `pass` — a repo already on the `hooks:`/`on_pre_build` surface is **conformant, not drift**. Only flag drift when no surface is wired at all, or when a surface contradicts the i18n rule in the next row. |
| Surface is legal for the repo's i18n mode | If `mkdocs.yml` configures `mkdocs-static-i18n` with `docs_structure: folder`, the surface **MUST** be one of the two physical-file surfaces (`on_pre_build` hook or standalone pre-build step). A `mkdocs-gen-files` script under folder-mode is `drift`: `mkdocs-static-i18n` 1.3.x discards files whose `abs_src_path` isn't under `docs_dir`, so gen-files pages are **silently dropped → empty catalog** (spec §Generation mechanism, §MkDocs extension-hook declaration → Baseline interaction). |
| `mkdocs.yml` declares `mkdocs-literate-nav` | Look for `literate-nav` in `plugins:`. |
| Plugin source roots are configured | Read `docs/catalog-sources.yml` (a sibling YAML under `docs_dir`, per spec §Generation mechanism) for a list pairing each local source path with its public repo URL; the generator reads that file, not `mkdocs.yml`. |
| Source roots match the detected mode | In plugin mode, the local path `.` (or `skills/` + `agents/`) with the repo's own `https://github.com/<owner>/<repo>` URL must be present. In consumer mode, at least one external source root must be present and no local-plugin entry should be declared. |
| Skills and Agents navigation sections exist | Inspect `nav:` for stable top-level entries. Literate-nav `SUMMARY.md` files produced by the generator also satisfy this. |
| Section index pages link to `by-task.md` | Read `docs/<lang>/skills/index.md` and `docs/<lang>/agents/index.md` for each configured language; both must contain a prominent link to `../by-task.md` (spec §Navigation and layout). |
| Tag index page exists | Either declared in `nav:` or generated as `docs/tags.md`. |
| Task-oriented landing page exists per language | `docs/<lang>/by-task.md` exists for every configured docs language (spec §Task-oriented landing pages). Generator emits a one-shot skeleton; hand-curated pages carry an ISO-8601 `last_updated`. |
| Generator uses a standard YAML parser | Inspect the generator hook; it must hand source frontmatter to `yaml.safe_load` (or equivalent), not a flat-line custom parser — `dont_use_when` and `examples` (lists of mappings, spec §Use-case metadata) require nested-mapping support. |
| Source frontmatter respects use-case schema | Walk every source `SKILL.md` / `agents/<name>.md`. When `summary`, `summary_<lang>`, `use_when`, `dont_use_when`, `see_also`, or `examples` is declared, it conforms to the schema in spec §Use-case metadata (string limits, key sets, entry counts). Unresolvable `dont_use_when[].alternative` or `see_also[]` values fail the docs build. |
| Source frontmatter `tags` are clean of auto-tags | No source `tags` entry begins with `_`. The reserved auto-tag `_translation-pending` (spec §Per-language short summary) must be generator-emitted only; an author-declared `_…` tag fails the docs build. |
| Committed-catalog policy matches the deploy surface | Run `git ls-files docs/**/skills/ docs/**/agents/ docs/**/tags.md 2>/dev/null`. Which state is `pass` depends on the surface (spec §Generation mechanism, two mechanisms): **(a) Deploy-time generation (preferred)** — when the deploy pipeline regenerates on every build (the `on_pre_build` hook fires inside every `mkdocs build`/`mkdocs gh-deploy`; or the reusable runs `task docs`; or a `gen-files` script runs in the plugin build) — the tree **MUST NOT** be committed, so any git-tracked hits are `drift`. **(b) Committed catalog with a freshness gate (fallback)** — when the shared deploy reusable doesn't run the generator (for example it deploys a bare `mkdocs build` that never invokes `task docs`) — the tree **MUST** be committed **and** guarded by a CI freshness check that fails on drift; here a committed tree is `pass` and a *missing* freshness gate is `drift`. Don't flag a committed tree as drift on the fallback; the `on_pre_build` hook is the recommended way to exit the fallback. |
| The generator runs inside the normal docs build | Confirm the wired surface regenerates with no separate manual step: the `on_pre_build` hook satisfies this inside `mkdocs build` itself (no Taskfile needed); a standalone pre-build step satisfies it by being a `Taskfile.yml` `docs`-target dependency; a `gen-files` script satisfies it within the plugin build. |
| Docs deps include the surface's plugins plus `pyyaml` | Read `docs/requirements.txt` / `pyproject.toml` `docs` extras / `requirements/docs.txt`, whichever the repo uses. `mkdocs-literate-nav` and `pyyaml` are required for **every** surface (`pyyaml` for the standard-YAML parsing rule above). `mkdocs-gen-files` is required **only** for the gen-files surface; the `on_pre_build` hook and standalone pre-build step write physical files and need no gen-files dependency. |
