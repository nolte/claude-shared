# Gotchas

The non-obvious facts this audit gets wrong most often. Referenced from `SKILL.md` §Gotchas; read this file when triaging a finding whose severity or ownership is unclear.

- **Wiring is static; the tracker's behaviour is runtime.** The mandatory floor is that the SDK, the tagging, the sampling decision, and the scrubbing hook are *wired*. Alert owners, triage service levels, issue-lifecycle honesty, and retention live in the tracker, not the repo — document them, never statically fail them.
- **"No DSN" is conformant in development and a violation in production.** The requirements are lifecycle-phase-dependent, so a bare absence is never the finding by itself; the adoption ruling rests on repository-declared deployment evidence plus a recorded exception, never on a guess about real-user exposure.
- **A DSN is not a credential — judge the source, not the visibility.** A browser bundle necessarily exposes its DSN, so "it's readable" is never the finding. What the spec forbids is a DSN literal *in the source tree*. Stage portability — an artifact that cannot be redeployed without a rebuild — is a genuine weakness of a build-baked DSN, but the spec does not currently mandate against it, so it is reported as a Warning and never used to manufacture a hard fail.
- **A frozen `release` is worse than an obvious gap.** It looks wired and silently destroys regression detection. Report it as a stale release constant, never as "release present".
- **You check that scrubbing is wired, not the PII verdict** (owned by `gdpr-data-protection-reviewer`); audit the producing side only.
- **The tool class is the contract, not the vendor.** GlitchTip is the non-binding reference profile; never fail a component for using Sentry, Bugsink, or another capability-class-compliant tracker. A *non-protocol* client (Bugsnag, Rollbar) is a different matter — that breaks the swappability MUST and is a hard fail, not an un-instrumented component.
- **The one lifecycle violation you can see from the source tree** is a committed development or local configuration path pinning a production `environment` value or a production DSN. Everything else about the development, staging, and production phases needs a running system; this one does not, which is why it is a hard fail.
- **A package name in a manifest is not a dependency declaration.** A linter or type-checker stanza naming the SDK to silence it reads as a declaration to a careless check, while the real declaration sits in a sibling manifest. The scanner guards this; do not undo it by re-deriving the finding from a name match.
