# Capability Reach Audit

Establish, per capability a repository **declares**, whether the executing path reaches the scope it declares, by running something rather than reading something. The deliverable is a **versioned probe set** under `project/reach-probes/` in the audited repository; the report under `.audits/capability-reach/` is regenerated by executing that set and is never maintained by hand.

Implements `spec/project/capability-reach-audit/`: the spec defines the four declaration sources, the probe (observation point outside the artefact, raw output as evidence, no self-reported success), the three environment tiers, the derive → approve → persist → execute lifecycle, and the report contract. This skill binds those rules to the on-disk procedure and owns the operator dialogue, the approval gate, persistence, the runner invocation, and the summary. Derivation belongs to the `capability-reach-scanner` agent; comparison and classification belong to the bundled runner. When the spec and this skill disagree, the spec wins.

## Inputs

- **Target**: the path of a **local working copy** of the audited repository. Default: the current working directory. A remote address is never accepted (see Preconditions).
- **Operation**: `derive`, `run` (default), or `report`. When `run` finds no probe set, it routes to `derive`.
- **T2 opt-in**: off by default. Only an explicit operator request ("include T2", "full stack too") turns it on.
- **Entry filter** (`derive` only): probe ids to re-derive, used after `run` reported stale probes.
- **Environment timeout** (`run` only): forwarded as `--environment-timeout SECONDS` when the operator names one; otherwise the runner's default applies.

## Preconditions

1. **Local working copy (R13).** Before dispatching anything, refuse the target when it is a remote address (`scheme://…` or `user@host:…`), not a directory, has no `.git` at its root, or `git -C <path> rev-parse --show-toplevel` resolves elsewhere (a subdirectory or a bare repository). Name the reason in the runner's own wording: the audit executes probes against the checked-out system, so it needs a local working copy; clone the repository and pass its path. There is no remote mode.
2. **Governing spec.** Read `spec/project/capability-reach-audit/en.md` from the target or from the installed `nolte-shared` plugin; if neither resolves, stop and say so rather than working from memory.
3. **Resume scan.** Check `.resume/capability-reach-audit/` for an `in_progress` run with matching inputs before asking anything (see Resumability).

## Operations

### `derive` (inventory, approval gate, persistence)

1. **Dispatch the scanner.** Dispatch `capability-reach-scanner` (Agent) with the target path and, when present, the entry filter. It returns one YAML payload: `sources.{requirement,endpoint,capability,inventory}.presence` each `present`, `absent`, or `skipped` (with a sibling `reason`); `entries[]` carrying either a schema-conformant `probe` plus `assumes[]` or a `not_constructible` reason code (`scope_not_countable`, `needs_model_judgement`, `effect_in_third_party`, `missing_environment_target`, `missing_observation_helper`) with the free text in `detail`; and `totals{entries, drafted, not_constructible}`. Wait for the payload; never draft probes yourself in parallel. Checkpoint (`phase: derived`) with the payload under `state:`.
2. **Summarise before asking.** Report the four sources' presence, the entry count, the drafted count, and the not-constructible count grouped by reason code, so the operator sees how much of the declared surface can be probed at all. When all four sources are `absent`, that is the result (R15): report it, write only the empty manifest of step 5, and stop.
3. **Approval, batched by source.** Present drafts in the fixed order requirement → endpoint → capability → inventory, one batch per source, split into sub-batches of at most twelve when a source has more. Read `references/approval-batching.md` when rendering a batch or interpreting an answer: it fixes the batch table, the answer vocabulary (`approve all`, `approve <ids>`, `reject <ids>`, `skip`), and the checkpoint after each batch. Never one probe per turn when the set is large; never approve on the operator's behalf.
4. **Persist only the approved set (R4).** For each approved draft write `<target>/project/reach-probes/<id>.yml`: the draft as returned, plus `approval: {approved_at: "<UTC ISO 8601, quoted>", approved_by: "<git config user.name>"}`. Read `references/approval-batching.md` §Persistence for the exact file shape and the identity fallback when `user.name` is empty. Rejected and skipped drafts are written nowhere. Checkpoint (`phase: persisted`).
5. **Record the remainder.** Write `<target>/project/reach-probes/_not-constructible.yml` on **every** derive round, even as `entries: []`: the runner reads an empty manifest as "every declared entry received a probe" and an absent one as "the derivation never recorded it", and only this step can make that distinction true. One entry per `not_constructible` the scanner returned (`id`, `declaration` as returned, `reason` code, optional `detail`, `derived_from`, `recorded_at` UTC, quoted); a draft the operator rejected or skipped at the gate is **not** a manifest entry. Read `references/approval-batching.md` §Not-constructible manifest for the file shape and the per-code proposal: `missing_environment_target` and `missing_observation_helper` are proposed as work in the target repository, since those two are the ones the operator can act on. The runner counts every manifest entry as not probed in the headline.
6. **Say what must happen next.** The runner compares history, so the operator must **commit the probe set** before `run` can execute it; an uncommitted probe is reported not probed. Recommend one commit per derive round that touches only `project/reach-probes/`.

### `run` (execute the stored set; default)

1. **Invoke the runner exactly as:**

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/skills/capability-reach-audit/scripts/reach_audit.py" --repo <path>
   ```

   Append `--include-t2` only when the operator asked for T2 (R8), and `--environment-timeout SECONDS` only when the operator named a bound. Run `scripts/reach_audit.py` to execute the probes; it loads the set, decides per probe from git history whether it may run (declaration changed → stale, probe changed → weakened), runs environment targets and observation steps, classifies, and writes the report. Never reimplement any of that, and never invoke it by a repo-relative path.
2. **Map the exit code.** Read `references/runner-exit-codes.md` when the runner exits non-zero or when the report lists not-probed reasons: it maps exit 0 to `report`, exit 3 (no probe file, with or without manifest entries) to `derive`, exit 4 (findings: weakened or invalid probes, contradictions, manifest defects) to leading with those, exit 5 to the runner's `pip install` hint verbatim, and the not-probed reasons `declaration changed since derivation`, `probe file is not committed`, and `not constructible: <code>` to their next step.
3. **Surface the report** as in `report`. For stale probes, offer `derive` with the entry filter set to exactly those ids (R5: re-derive only what changed).

### `report` (read the latest report)

1. Locate the newest `<target>/.audits/capability-reach/<YYYY-MM-DD>.md`. If none exists, route to `run`.
2. Lead with the headline exactly as the runner wrote it, including the `<k> of them not constructible` clause and, when present, the sentence that the manifest is absent or unreadable, then the Provenance section verbatim, then the reach-per-tier table and the Findings section. Quote the reach ratio and the `Measured by` command per probe as written.
3. Never edit that file, never recompute a ratio, and never restate a class the runner did not assign. The report is the runner's; the summary is yours.

## Gotchas

- **`${CLAUDE_PLUGIN_ROOT}` is load-bearing.** The runner lives in the installed plugin directory, not in the audited repository. A bare `skills/capability-reach-audit/scripts/…` path works only inside `claude-shared` and breaks in every consumer. Data paths (`--repo`) stay relative to the operator's working directory; only the script path is plugin-rooted.
- **The runner needs PyYAML and jsonschema.** Exit 5 prints the install hint; relay it verbatim and stop. Never parse or validate probes yourself as a fallback.
- **Any later commit to a probe file is a weakening.** The baseline is the commit that recorded the probe's current `derived_from`; every commit touching the file afterwards, including a reformat, makes it `weakened` and not probed. The fix is a re-derive and re-approve with a new `derived_from`, never an edit.
- **Stale is not an error.** `declaration changed since derivation` means the declaration moved; the probe is withheld, not failed. Route to `derive` with the entry filter.
- **`approved_at` is quoted.** Unquoted, the YAML loader turns it into a timestamp object and the probe fails the schema.
- **An absent manifest is not an empty one.** Without `project/reach-probes/_not-constructible.yml` the headline reads `Not probed: <n> of <total> probes.` plus a sentence that entries the derivation could not probe are not counted; with it, `Not probed: <n> of <total> entries, <k> of them not constructible.` Every derive round writes the file, even empty. An id that is both a probe file and a manifest entry is a `contradiction` finding, and that probe is not executed.
- **T2 is silent unless requested.** Without `--include-t2` every T2 probe is `not probed` with reason `tier T2 not requested`, and the report says so in Provenance; that is honest output, not a failure to fix by adding the flag on your own.
- **A T0 result establishes that something ran, never that it works.** Don't read a reached T0 probe as correctness.

## Resumability

Per `spec/claude/resumable-work/`, this skill is `resumable: true`. State is persisted to `.resume/capability-reach-audit/<run-id>.yml` after each named phase boundary (`derived`, `approved-<source>` after each batch, `persisted` once probes and manifest are written, `executed`, `reported`), with the scanner payload and the approval decisions under `state:` and `decisions[]`. The checkpoint after each approval batch is the load-bearing one: on resume no batch already answered is asked again. On re-invocation, scan that directory for files with `status: in_progress` whose `inputs:` snapshot (target path, operation, T2 opt-in, entry filter) matches; if one matches, prompt `Resume run <run_id> from phase <phase> (last checkpoint <last_checkpoint_at>)? [resume / start-new / discard]`. The envelope and the fail-closed semantics on schema or YAML errors are load-bearing in the spec; don't duplicate them here.

## Hard rules

- **Never** persist an unapproved probe: no draft reaches `project/reach-probes/` without an operator answer naming it, and no `approval` block is written on the operator's behalf.
- **Never** write in the target outside `project/reach-probes/` and `.audits/capability-reach/`; the runner owns the second, this skill the first.
- **Never** compare observed against expected, classify an entry, or compute a ratio in conversation; the runner does it, and the report is quoted, not recomputed.
- **Never** edit a report by hand or under `.audits/capability-reach/` at all.
- **Never** pass `--include-t2` without the operator's explicit request in this run.
- **Never** invoke the runner by a repo-relative path; only `"${CLAUDE_PLUGIN_ROOT}/skills/capability-reach-audit/scripts/reach_audit.py"`.
- **Never** accept a remote address, a bare repository, or a subdirectory as the target; there is no remote mode.
- **Never** drop a `not_constructible` entry from the manifest or present it as reached, not reached, or a gap in the inventory; never list a rejected or skipped draft in the manifest; never skip writing the manifest on a derive round.
- **Never** write a probe whose `approved_by` is empty; ask for the operator identity instead.
- When `spec/project/capability-reach-audit/` and this skill disagree, the spec wins; this skill needs the update.

## Why this is a skill, not an agent

This skill follows the hybrid pattern: derivation is delegated to the read-only `capability-reach-scanner` agent, comparison to the bundled runner, while the approval gate, persistence, the invocation, and the summary stay in the skill.

- **Mid-flow interactivity**: the approval gate is the spec's load-bearing control between derivation and persistence; it is an operator dialogue, batched but interactive, which an agent cannot hold.
- **Persistent artefact**: the probe set under `project/reach-probes/` is the durable deliverable and lives in the audited repository; skills own persistent, operator-approved state.
- **Orchestration role**: one run dispatches an agent, invokes a script, and reads a file back into the conversation so the operator can decide what to commit and what to re-derive.
- **Counter-dimension**: building the inventory means reading every requirement, workflow trigger, README claim, and inventory file, which is exactly the context-window pressure that favours an agent. That pull is honoured for the derivation half, delegated to `capability-reach-scanner`; the approval gate and the persistent probe set keep the orchestrating surface a skill.
