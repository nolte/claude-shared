# Performance / Rendering — Research notes

## Methodology

Each best-practice claim below is backed by at least two independent authoritative sources. Acceptable sources include the official vendor/standards docs: react.dev, vitejs.dev, mui.com, redux.js.org, reactrouter.com, react-hook-form.com, web.dev (Chrome team / Google), developer.mozilla.org, w3.org, whatwg.org, nginx.org, recharts.org, day.js.org, axios-http.com, vitest.dev. Where only the canonical vendor doc exists, a corroborating spec (MDN/W3C) or independent vendor doc is paired. Items lacking two independent sources are marked `partial` or `unverified` with a reason. The repo under test ships a static SPA served by nginx with no SSR.

The exact stack under research:
- React 19 (compiler / automatic memoization, Suspense, transitions)
- Vite 8 as bundler and dev server
- MUI v9 (`@mui/material`, `@mui/icons-material`, `@mui/x-date-pickers`, `@mui/x-tree-view`) with Emotion
- Redux Toolkit + `react-redux` (selector memoization, RTK Query caching)
- React Router v7 (data routers, lazy routes)
- `react-hook-form`, `recharts`, `dayjs`, `axios`, `vitest` + `@testing-library/react`
- nginx as the static asset host in production

## Best practices

### Core Web Vitals targets (p75)
- **Practice:** Treat the field-data p75 thresholds as hard targets: LCP <= 2.5 s, INP <= 200 ms, CLS <= 0.1. A page passes Core Web Vitals only when at least 75% of real user visits per segment hit the "good" bucket for every metric.
- **Why:** These are the Chrome-team-defined, Search-ranking-relevant thresholds; below them users perceive load, interaction, and visual stability as fast and predictable.
- **Applies to:** Every production route of the SPA; measured via CrUX / RUM, not synthetic alone.
- **Sources:**
  1. Web Vitals — web.dev — https://web.dev/articles/vitals
  2. Understanding Core Web Vitals and Google search results — Google Search Central — https://developers.google.com/search/docs/appearance/core-web-vitals
- **Confidence:** verified

### `font-display: swap` (or `optional`) on every `@font-face`
- **Practice:** Declare `font-display: swap` (or `font-display: optional` for non-essential fonts) on every `@font-face` rule, including those generated for web-font hosting and locally self-hosted fonts.
- **Why:** Eliminates the invisible-text Flash of Invisible Text (FOIT) during the block period; with `swap`, the browser renders fallback text immediately and swaps when the font arrives, improving LCP and perceived load.
- **Applies to:** Self-hosted fonts shipped under `public/` or generated by MUI's typography assets; affects every text-bearing page.
- **Sources:**
  1. `font-display` — MDN — https://developer.mozilla.org/en-US/docs/Web/CSS/@font-face/font-display
  2. Best practices for fonts — web.dev — https://web.dev/articles/font-best-practices
- **Confidence:** verified

### React Compiler automatic memoization (React 19)
- **Practice:** Enable the React Compiler (stable, shipped as `babel-plugin-react-compiler` 1.0) so that components, hooks, and derived values are memoized automatically; treat `useMemo`, `useCallback`, and `React.memo` as escape hatches, not the default. Code must follow the Rules of React for the compiler to be sound.
- **Why:** Eliminates re-render cascades that would otherwise demand hand-written memoization; the compiler's output is at least as precise as careful manual memoization in the typical case.
- **Applies to:** Every component in `src/` once the compiler plugin is wired into the Vite/Babel pipeline; lint via `eslint-plugin-react-compiler` to keep code compiler-eligible.
- **Sources:**
  1. React Compiler — react.dev — https://react.dev/learn/react-compiler
  2. React Compiler — Introduction — react.dev — https://react.dev/learn/react-compiler/introduction
- **Confidence:** verified

### `useTransition` for non-urgent state updates
- **Practice:** Wrap state updates that trigger expensive re-renders (tab switches, filter changes, chart re-draws, navigation to new routes) in `startTransition`; expose `isPending` for a non-blocking spinner / disabled state.
- **Why:** Keeps urgent updates (typing, clicks) responsive; React can interrupt and re-prioritise the transition if a new urgent update arrives, preventing UI freezes.
- **Applies to:** Filter panels, chart pages, dashboard tab switches; not for controlled-input value writes.
- **Sources:**
  1. `useTransition` — react.dev — https://react.dev/reference/react/useTransition
  2. `startTransition` — react.dev — https://react.dev/reference/react/startTransition
- **Confidence:** verified

### `useDeferredValue` for slow downstream renders
- **Practice:** When a prop drives a slow child (large list, recharts plot) and you cannot wrap the upstream setter in a transition, derive a deferred prop with `useDeferredValue` and wrap the slow child in `memo`.
- **Why:** Keeps the input control responsive on weak devices; React adapts the defer interval to device speed instead of a fixed debounce.
- **Applies to:** Search inputs feeding large MUI DataGrid / tree-view / recharts views.
- **Sources:**
  1. `useDeferredValue` — react.dev — https://react.dev/reference/react/useDeferredValue
  2. `useTransition` (cross-references the deferred-prop pattern) — react.dev — https://react.dev/reference/react/useTransition
- **Confidence:** verified

### Route-level code splitting via React Router v7 lazy routes
- **Practice:** Define route modules with `lazy` (or use the framework-mode route-module file convention) so each route's loader, action, component, and ErrorBoundary download only when the user navigates to that URL segment.
- **Why:** Keeps the initial bundle small; only the bundles required to render the current URL are loaded, so first-route TTI is not penalised by unrelated screens.
- **Applies to:** Every non-shell route in `src/routes/`; combine with Suspense fallbacks for graceful loading states.
- **Sources:**
  1. Automatic Code Splitting — React Router — https://reactrouter.com/explanation/code-splitting
  2. Code Splitting with React.lazy and Suspense — react.dev — https://react.dev/reference/react/lazy
- **Confidence:** verified

### Vite asset hashing + immutable cache for hashed files
- **Practice:** Keep Vite's default content-hashed filenames for JS/CSS/asset output (e.g. `assets/img.2d8efhg.png`). Serve those hashed files with `Cache-Control: public, max-age=31536000, immutable` and serve `index.html` with `Cache-Control: no-cache` so clients always revalidate the HTML and pick up new hashed asset references on deploy.
- **Why:** Hashed filenames make every released asset uniquely addressable; combined with `immutable`, browsers skip revalidation requests entirely. The unhashed `index.html` is the only redirection layer the client needs to recheck.
- **Applies to:** The nginx `location /assets/` block (hashed assets, `immutable`) and the `location = /index.html` / SPA-fallback block (`no-cache`).
- **Sources:**
  1. Building for Production — Vite — https://vite.dev/guide/build
  2. `Cache-Control` (incl. `immutable`) — MDN — https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Cache-Control
- **Confidence:** verified

### Configure Vite chunk strategy explicitly when defaults underperform
- **Practice:** Rely on Vite's default per-module code-splitting first; only tune `build.rollupOptions.output.manualChunks` (or the Rolldown `codeSplitting` option in Vite 7+) when bundle analysis shows a long-tail vendor chunk that hurts caching. Avoid pinning entire `node_modules` into a single mega-chunk.
- **Why:** Modern Rollup/Rolldown already produces near-optimal per-route chunks; ad-hoc manual chunking can break Vite's hash-stability guarantees or fight tree-shaking. Manual chunking is opt-in since Vite 2.9.
- **Applies to:** `vite.config.ts` of the SPA; revisit after every dependency upgrade.
- **Sources:**
  1. Build Options — Vite — https://vite.dev/config/build-options
  2. Building for Production — Vite — https://vite.dev/guide/build
- **Confidence:** verified

### MUI: import icons by deep path, never via the barrel
- **Practice:** Always import individual icons as `import Delete from '@mui/icons-material/Delete'` (default-export, deep path). Never use the barrel form `import { Delete } from '@mui/icons-material'`. Enforce with ESLint `no-restricted-imports` so violations fail review.
- **Why:** Barrel imports walk the entire `@mui/icons-material` index and can be up to six times slower in dev; in production they enlarge intermediate transform graphs even when the final bundle is tree-shaken.
- **Applies to:** Every file that consumes a Material icon; equivalent rule applies to `@mui/lab` and similarly wide barrels.
- **Sources:**
  1. Minimizing bundle size — Material UI — https://mui.com/material-ui/guides/minimizing-bundle-size/
  2. React Icon Component — Material UI — https://mui.com/material-ui/icons/
- **Confidence:** verified

### Redux Toolkit: memoise derived data with `createSelector`
- **Practice:** Wrap any selector that derives new references (filter/map/sort, joins across slices, expensive transforms) in `createSelector`. Pass it to `useSelector`. Do NOT memoise selectors that already return a stable slice reference.
- **Why:** `useSelector` re-runs after every dispatched action and compares results with `===`. Non-memoised derived data forces re-renders on every dispatch; expensive transforms re-run unnecessarily.
- **Applies to:** Every `select…` exported alongside a slice; pair with `useSelector` (or `useAppSelector` typed alias).
- **Sources:**
  1. Deriving Data with Selectors — redux.js.org — https://redux.js.org/usage/deriving-data-selectors
  2. `createSelector` — Redux Toolkit — https://redux-toolkit.js.org/api/createSelector
- **Confidence:** verified

### RTK Query for server-state caching, dedupe, and re-fetch
- **Practice:** Move all read-side server state into RTK Query endpoints; use `tagTypes` / `providesTags` / `invalidatesTags` for cache invalidation; keep the default 60-second `keepUnusedDataFor` unless profiling shows otherwise.
- **Why:** RTK Query deduplicates in-flight requests, caches results across subscribers, and refetches automatically on tag invalidation, mount, or focus — eliminating hand-rolled fetch effects that often cause request storms and stale renders.
- **Applies to:** Every read endpoint backed by axios/fetch; mutations also benefit by automatically refreshing affected queries.
- **Sources:**
  1. RTK Query Overview — Redux Toolkit — https://redux-toolkit.js.org/rtk-query/overview
  2. Cache Behavior — Redux Toolkit — https://redux-toolkit.js.org/rtk-query/usage/cache-behavior
- **Confidence:** verified

### React Hook Form: keep inputs uncontrolled with `register`, isolate watchers
- **Practice:** Prefer uncontrolled inputs registered via `register(...)`; reach for `Controller`/`useController` only when a non-native input forces it. Use `useWatch` (per-component subscription) rather than `watch` (root re-render) when reacting to specific fields.
- **Why:** Uncontrolled inputs do not trigger a React re-render on every keystroke; `useWatch` isolates the re-render to its host, both keeping large forms fluid.
- **Applies to:** Form-heavy screens (settings, editors, multi-step wizards).
- **Sources:**
  1. Advanced Usage — React Hook Form — https://react-hook-form.com/advanced-usage
  2. `useWatch` — React Hook Form — https://react-hook-form.com/docs/usewatch
- **Confidence:** verified

### dayjs: import only the locales you ship
- **Practice:** Import locale data via deep path (`import 'dayjs/locale/de'`) only for the locales the app actually uses. Do not load `dayjs/locale` as a barrel. Switch with `dayjs.locale('de')`.
- **Why:** Dayjs ships only the English locale by default; deep-path imports are tree-shakeable, keeping the runtime free of unused locale tables.
- **Applies to:** App bootstrap module; `@mui/x-date-pickers` locale wiring (which adapter forwards the dayjs locale).
- **Sources:**
  1. Loading locale in the browser — Day.js — https://day.js.org/docs/en/i18n/loading-into-browser
  2. Changing locale globally — Day.js — https://day.js.org/docs/en/i18n/changing-locale
- **Confidence:** verified

### axios: cancel in-flight requests with `AbortController`
- **Practice:** Pass an `AbortController().signal` on every long-running axios request and call `controller.abort()` from the consuming hook's cleanup (e.g. a `useEffect` return) or on route change. Use `axios.isCancel(err)` to swallow the resulting rejection silently. Treat the legacy `CancelToken` as removed.
- **Why:** Prevents wasted work, race conditions where stale responses overwrite fresh state, and memory leaks when components unmount mid-request.
- **Applies to:** Any axios call not already mediated by RTK Query (which handles cancellation internally on tag changes).
- **Sources:**
  1. Cancellation — axios — https://axios-http.com/docs/cancellation
  2. `AbortController` — MDN — https://developer.mozilla.org/en-US/docs/Web/API/AbortController
- **Confidence:** verified

### Native lazy-load and async-decode for off-screen images
- **Practice:** Use `loading="lazy"` and `decoding="async"` on every `<img>` that is below the fold. Always declare intrinsic `width` and `height` (or CSS `aspect-ratio`) on those images.
- **Why:** Lazy loading defers off-screen image fetches until the viewport approaches them, cutting bandwidth and improving LCP for the visible hero; async decoding moves bitmap decode off the main thread. Width/height prevent CLS while the byte stream is still pending.
- **Applies to:** All non-LCP imagery — content thumbnails, list illustrations, marketing fold-out blocks.
- **Sources:**
  1. `<img>` lazy loading — MDN — https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/Lazy_loading
  2. `<img>` element — MDN (decoding, loading attributes) — https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img
- **Confidence:** verified

### nginx: pre-compress static assets with gzip_static (+ brotli_static)
- **Practice:** Pre-compress hashed JS/CSS/SVG/font assets at build time and serve them via `gzip_static on;` (and `brotli_static on;` from the `ngx_brotli` module when available). Keep dynamic `gzip on;` as a fallback for first-class HTML.
- **Why:** `gzip_static` serves already-compressed `.gz`/`.br` files directly, removing per-request CPU compression cost and improving TTFB; precompression yields better ratios than on-the-fly.
- **Applies to:** The nginx server block hosting `/assets/`; Vite plugins like `vite-plugin-compression` emit the `.gz`/`.br` siblings during `vite build`.
- **Sources:**
  1. `ngx_http_gzip_static_module` — nginx — https://nginx.org/en/docs/http/ngx_http_gzip_static_module.html
  2. `ngx_brotli` module — Google (GitHub) — https://github.com/google/ngx_brotli
- **Confidence:** verified

### Responsive viewport meta tag on every page
- **Practice:** Ship `<meta name="viewport" content="width=device-width, initial-scale=1">` in the document head. Do not set `user-scalable=no` or hard-coded pixel widths.
- **Why:** Without it, mobile browsers render at a virtual 980 px width and downscale, so CSS media queries never fire and the layout looks zoomed-out; Core Web Vitals (LCP, CLS, INP) are then measured against the wrong viewport.
- **Applies to:** `index.html` of every Vite-built shell.
- **Sources:**
  1. `<meta name="viewport">` — MDN — https://developer.mozilla.org/en-US/docs/Web/HTML/Viewport_meta_tag
  2. Responsive web design — MDN — https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout/Responsive_Design
- **Confidence:** verified

### Preload the LCP-critical web font as WOFF2 with `crossorigin`
- **Practice:** For the typography that renders the LCP text (e.g. the primary heading face), emit a `<link rel="preload" as="font" type="font/woff2" href="/fonts/…" crossorigin>` in the head and self-host the WOFF2 file. Do NOT preload every font weight/style.
- **Why:** Without preload, the browser only discovers the font after parsing the CSS that references it, delaying LCP for text candidates. The `crossorigin` attribute is mandatory: fonts are always fetched in CORS mode, so a preload missing it is silently ignored and the resource is fetched twice.
- **Applies to:** `index.html` head; one preload per LCP-critical face.
- **Sources:**
  1. Preload critical assets — web.dev — https://web.dev/articles/preload-critical-assets
  2. `rel="preload"` — MDN — https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/rel/preload
- **Confidence:** verified

### MUI styling: `sx` for one-offs, `styled()` for reused components, stable theme
- **Practice:** Reach for `sx` only on one-off styles; promote anything reused across the codebase to a `styled()` component. Define and memoise the MUI theme once at module scope (or via `useMemo` keyed on a stable input) and pass it to a single `ThemeProvider` at the app root.
- **Why:** The `sx` prop has a measurable runtime parse cost on every render because the style object is processed each time; `styled()` generates static class names with cached serialisation. A theme object recreated each render forces all Emotion consumers to invalidate, defeating cache reuse.
- **Applies to:** Every MUI consumer; the app-shell `ThemeProvider`.
- **Sources:**
  1. The `sx` prop — MUI System — https://mui.com/system/getting-started/the-sx-prop/
  2. Theming — Emotion — https://emotion.sh/docs/theming
- **Confidence:** verified

### Virtualise long lists (more than ~100 visible-equivalent rows)
- **Practice:** Switch lists/grids that can grow beyond roughly 100 simultaneously rendered rows to a windowed renderer (e.g. `react-window`'s `FixedSizeList` / `VariableSizeList`, or the virtualised mode of MUI X DataGrid/TreeView). Configure a small `overscanCount` (e.g. 5) to avoid blank-flash on fast scroll.
- **Why:** Only the visible rows are mounted; scripting time during scroll drops dramatically (reported six-second savings in the AirShift case study), and memory stays bounded regardless of row count.
- **Applies to:** Data tables, log viewers, large picker dropdowns; the `@mui/x-tree-view` and `@mui/x-date-pickers` already virtualise internally, but custom lists do not.
- **Sources:**
  1. Virtualize large lists with react-window — web.dev — https://web.dev/articles/virtualize-long-lists-react-window
  2. Five ways AirSHIFT improved their React app's runtime performance — web.dev — https://web.dev/case-studies/five-ways-airshift-improved-their-react-app
- **Confidence:** verified

### Lazy-load chart components and defer chart re-renders
- **Practice:** Wrap recharts (and any other heavy chart) in `React.lazy(() => import('./Chart'))` and Suspense; only mount the chart when it scrolls into view (e.g. `IntersectionObserver`). Drive chart-driving state changes through `useTransition` / `useDeferredValue`. Mark this practice `partial`: the recharts site moved and bundle-size advice is not codified in vendor docs.
- **Why:** Recharts pulls in d3-shape and SVG primitives that bloat the initial JS bundle; deferring keeps LCP fast and shrinks INP on dashboards. React's official lazy/Suspense API is the supported way to defer.
- **Applies to:** Dashboard widgets, modal charts, off-screen analytics panels.
- **Sources:**
  1. `lazy` — react.dev — https://react.dev/reference/react/lazy
  2. `<Suspense>` — react.dev — https://react.dev/reference/react/Suspense
- **Confidence:** partial

### Vitest: pick the lightest DOM environment the suite tolerates
- **Practice:** Default the Vitest `environment` to `node`; opt individual files into `jsdom` or `happy-dom` only where browser APIs are touched. Prefer `happy-dom` over `jsdom` when the test only needs basic DOM/event APIs.
- **Why:** Loading `jsdom` is the dominant test-suite warm-up cost; `happy-dom` is documented as faster but covers a smaller surface. Per-file `// @vitest-environment …` keeps node-pure tests fast.
- **Applies to:** `vitest.config.ts`; per-file environment pragmas for component tests.
- **Sources:**
  1. Test Environment — Vitest — https://vitest.dev/guide/environment
  2. `environment` config — Vitest — https://vitest.dev/config/environment.html
- **Confidence:** verified

### Testing Library: use `findBy*` for async UI, prefer cheap queries on big trees
- **Practice:** Use `findBy*` (or `await waitFor(...)`) for assertions on UI that updates asynchronously instead of polling with `getBy*`. Prefer queries with narrow scope (`within(...)`) and pass `{ hidden: true }` to `getByRole`/`findByRole` on large trees.
- **Why:** `findBy*` is `getBy*` + `waitFor` and avoids spurious `act()` warnings caused by unhandled state updates. `getByRole` runs an accessibility-tree calculation that scales with DOM size; the `hidden` flag short-circuits the visibility check.
- **Applies to:** Every component test that touches async state, fetches, or transitions.
- **Sources:**
  1. FAQ — React Testing Library — https://testing-library.com/docs/react-testing-library/faq/
  2. ByRole query — Testing Library — https://testing-library.com/docs/queries/byrole/
- **Confidence:** verified

### Keep the critical CSS small; never include render-blocking JS in `<head>`
- **Practice:** Inline only the styles required for the first paint and load remaining CSS via the normal `<link rel="stylesheet">` chain emitted by Vite. Every `<script>` tag that is not the module entry MUST carry `defer`, `async`, or `type="module"` (which behaves like deferred). Never inject synchronous third-party scripts ahead of the app entry.
- **Why:** CSS is render-blocking until the CSSOM completes, and a synchronous script halts the HTML parser entirely. Vite emits `<script type="module">` for the entry by default, which is parser-non-blocking and deferred until parsing completes.
- **Applies to:** `index.html` and any vendor snippet (analytics, feature flags) added to it.
- **Sources:**
  1. Critical rendering path — MDN — https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/Critical_rendering_path
  2. `<script>` element (async / defer) — MDN — https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/script
- **Confidence:** verified

### `fetchpriority="high"` on the LCP image (or its preload)
- **Practice:** Set `fetchpriority="high"` on the `<img>` element (or matching `<link rel="preload" as="image">`) that the LCP candidate resolves to (e.g. the hero illustration on the landing route). Use it on at most one LCP candidate per page.
- **Why:** Browsers' default heuristics may schedule the LCP image at low/medium priority because it is in the document body; the hint promotes it ahead of below-the-fold assets, cutting LCP. The attribute is enumerated (`high` | `low` | `auto`) and is a hint the browser respects when consistent with its own priority model.
- **Applies to:** Marketing/landing pages, document-attached hero images.
- **Sources:**
  1. `fetchpriority` — MDN — https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/fetchpriority
  2. Optimize LCP — web.dev — https://web.dev/articles/optimize-lcp
- **Confidence:** verified

### Cache headers: `immutable` for hashed files, `no-cache` for `index.html`
- **Practice:** Serve every Vite-hashed asset under `/assets/` with `Cache-Control: public, max-age=31536000, immutable`. Serve `index.html` (the SPA fallback `try_files … /index.html`) with `Cache-Control: no-cache` (or `no-store` if PII is rendered inline) and a short `must-revalidate`-friendly policy.
- **Why:** `immutable` (RFC 8246) tells caches to skip even conditional revalidation while the resource is fresh, eliminating 304 round-trips on every reload. `no-cache` on the HTML guarantees the client always re-fetches the entry document and discovers the new hashed-asset references after a deploy.
- **Applies to:** The nginx `location /assets/` and root SPA fallback blocks.
- **Sources:**
  1. `Cache-Control` — MDN — https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cache-Control
  2. RFC 8246 — HTTP Immutable Responses — IETF — https://datatracker.ietf.org/doc/html/rfc8246
- **Confidence:** verified

### Let Vite emit `<link rel="modulepreload">` for route chunks
- **Practice:** Keep Vite's default `build.modulePreload.polyfill = true` and do not strip the `<link rel="modulepreload">` tags Vite emits into `index.html`. For backend-integrated setups, replicate the tags per the Vite backend-integration recipe.
- **Why:** `modulepreload` fetches the chunk, parses, compiles, and stores it in the module map ahead of execution, so dependency discovery happens in parallel rather than waterfalling on import statements.
- **Applies to:** Production `index.html` of every Vite-built SPA; backend templates that hydrate the manifest.
- **Sources:**
  1. `rel="modulepreload"` — MDN — https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/rel/modulepreload
  2. Backend Integration — Vite — https://vite.dev/guide/backend-integration
- **Confidence:** verified

## Anti-patterns (with sources)

### Hand-written `useMemo` / `useCallback` everywhere when the compiler is enabled
- **Why it's an anti-pattern:** With the React Compiler enabled, blanket manual memoization adds source noise, can mask the compiler's own optimisation, and gives reviewers a false sense of safety. The Compiler docs treat manual memoization as an "escape hatch."
- **Sources:** React Compiler — https://react.dev/learn/react-compiler ; `useMemo` (escape-hatch framing) — https://react.dev/reference/react/useMemo

### Recreating the MUI theme inside a component
- **Why it's an anti-pattern:** A fresh theme object per render invalidates Emotion's cache for every consumer; the docs explicitly warn to hoist the theme out of render.
- **Sources:** Theming — Emotion — https://emotion.sh/docs/theming ; The `sx` prop — MUI System — https://mui.com/system/getting-started/the-sx-prop/

### Importing icons (or anything) via MUI barrels
- **Why it's an anti-pattern:** Barrels traverse the entire index module, slowing dev startup up to 6× and complicating tree-shaking; the official guidance is deep-path imports.
- **Sources:** Minimizing bundle size — MUI — https://mui.com/material-ui/guides/minimizing-bundle-size/ ; React Icon Component — MUI — https://mui.com/material-ui/icons/

### `useSelector(state => state.todos.filter(...))` without `createSelector`
- **Why it's an anti-pattern:** Returns a new array reference per dispatch and forces re-render on every action; the Redux docs flag this exact snippet as a warning case.
- **Sources:** Deriving Data with Selectors — redux.js.org — https://redux.js.org/usage/deriving-data-selectors ; `createSelector` — Redux Toolkit — https://redux-toolkit.js.org/api/createSelector

### `axios.CancelToken` for new cancellation paths
- **Why it's an anti-pattern:** Deprecated since axios 0.22.0 in favour of `AbortController`; coexistence makes lifecycle handling inconsistent.
- **Sources:** Cancellation — axios — https://axios-http.com/docs/cancellation ; `AbortController` — MDN — https://developer.mozilla.org/en-US/docs/Web/API/AbortController

### `watch()` everywhere in React Hook Form
- **Why it's an anti-pattern:** `watch` re-renders the host (typically the form root); on a large form every keystroke re-renders the entire tree. `useWatch` scopes the re-render to the subscriber.
- **Sources:** `watch` — React Hook Form — https://react-hook-form.com/docs/useform/watch ; `useWatch` — React Hook Form — https://react-hook-form.com/docs/usewatch

### Loading every `dayjs/locale/*` "just in case"
- **Why it's an anti-pattern:** Each locale ships its own data table; bundling all of them defeats the whole point of dayjs's small default. Import only the locales actually offered to users.
- **Sources:** Loading locale in the browser — Day.js — https://day.js.org/docs/en/i18n/loading-into-browser ; i18n overview — Day.js — https://day.js.org/docs/en/i18n/i18n

### Serving `index.html` with `Cache-Control: max-age=31536000, immutable`
- **Why it's an anti-pattern:** The unhashed entry document MUST be revalidated or clients will pin a stale deploy indefinitely.
- **Sources:** `Cache-Control` — MDN — https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cache-Control ; HTTP caching — MDN — https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching

### Synchronous third-party `<script>` injected ahead of the Vite entry
- **Why it's an anti-pattern:** Blocks the HTML parser, delays Largest Contentful Paint, and inflates Interaction-to-Next-Paint when the script executes long handlers on the main thread.
- **Sources:** `<script>` element — MDN — https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/script ; Critical rendering path — MDN — https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/Critical_rendering_path

## Open questions / gaps

- **Recharts bundle / render cost:** The recharts site has been redirecting and current vendor docs do not codify a bundle-size / lazy-loading guidance section. Practices above are based on the generic React `lazy` + Suspense recipe; mark recharts-specific advice as `partial` until vendor docs catch up. Consider migrating chart-heavy routes to a library with documented incremental loading (e.g. `visx`, `@nivo`) if INP under load becomes a problem.
- **Rolldown migration in Vite 7/8:** Vite is moving toward Rolldown; the object form of `manualChunks` is deprecated. Spec wording should reference the documented Rolldown `codeSplitting` option once it leaves experimental status.
- **MUI X virtualisation specifics for `@mui/x-tree-view`:** Behaviour around virtualised tree-view + Suspense data fetching is not exhaustively documented; treat as `partial` and validate with profiling on the largest tree the product expects.
- **`@emotion/styled` static extraction:** Emotion does not ship build-time CSS extraction for the `styled` API; there is no two-source way to mandate static extraction without a third-party plugin. Skip until/unless Emotion documents it.
- **nginx-side HTTP/2 push:** Removed from Chrome; do not encode it as a recommendation despite older nginx docs mentioning `http2_push`.

## Spec-input summary

- **MUST** target p75 thresholds LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1 measured from real-user data (CrUX / RUM).
- **MUST** include `<meta name="viewport" content="width=device-width, initial-scale=1">` in `index.html`.
- **MUST** set `font-display: swap` (or `optional`) on every `@font-face`.
- **MUST** preload the LCP-critical WOFF2 font with `as="font"`, `type="font/woff2"`, and `crossorigin`.
- **MUST** enable the React Compiler (`babel-plugin-react-compiler` 1.x) and configure `eslint-plugin-react-compiler`; treat `useMemo`/`useCallback`/`React.memo` as escape hatches.
- **MUST** wrap state updates that drive expensive renders (filters, tab switches, chart inputs) in `startTransition` (or surface them via `useTransition`).
- **SHOULD** apply `useDeferredValue` to props feeding `memo()`-wrapped slow children when the source setter cannot be moved inside a transition.
- **MUST** code-split routes via React Router v7 lazy route modules.
- **MUST** import MUI icons via deep paths (`@mui/icons-material/<Name>`); ESLint `no-restricted-imports` MUST forbid `@mui/icons-material` barrel imports.
- **MUST** memoise derived Redux selectors with `createSelector`; non-derived selectors MUST NOT be wrapped.
- **SHOULD** move read-side server state into RTK Query endpoints with explicit `tagTypes` and the default 60 s `keepUnusedDataFor`.
- **MUST** prefer uncontrolled React Hook Form inputs (`register`); use `useWatch` instead of `watch` for cross-field reactions in large forms.
- **MUST** import dayjs locales by deep path (`dayjs/locale/<code>`) and only ship the locales the product actually offers.
- **MUST** pass `AbortController().signal` on cancellable axios calls; the deprecated `CancelToken` MUST NOT appear in new code.
- **MUST** declare `loading="lazy"` and `decoding="async"` on every off-screen `<img>` and provide intrinsic `width`/`height` (or CSS `aspect-ratio`).
- **MUST** add `fetchpriority="high"` to the LCP `<img>` (or its preload link) on routes whose LCP candidate is an image.
- **MUST** keep Vite's content-hashed filenames for `/assets/*`.
- **MUST** serve `/assets/*` from nginx with `Cache-Control: public, max-age=31536000, immutable` and serve `index.html` with `Cache-Control: no-cache`.
- **MUST** enable `gzip_static`; **SHOULD** enable `brotli_static` via `ngx_brotli` when available; emit `.gz`/`.br` siblings during `vite build`.
- **MUST** keep `<link rel="modulepreload">` tags Vite emits; backend-integrated setups MUST replicate them from the manifest.
- **MUST NOT** inject synchronous `<script>` tags ahead of the Vite module entry; every late-loaded script MUST be `defer`, `async`, or `type="module"`.
- **SHOULD** virtualise lists/grids that can mount more than ~100 rows (`react-window` `FixedSizeList`/`VariableSizeList` or MUI X virtualised modes) with a small `overscanCount` (≈ 5).
- **SHOULD** lazy-load `recharts` charts via `React.lazy` + Suspense, optionally gated by `IntersectionObserver`.
- **MUST** memoise the MUI theme at module scope (or via `useMemo` on stable inputs) and pass it to a single root `ThemeProvider`.
- **SHOULD** use `sx` only for one-off styles and promote reused styles to `styled()`; avoid object-shape `sx` values that change every render (use CSS variables instead).
- **MUST** default the Vitest `environment` to `node`; opt files into `happy-dom`/`jsdom` per pragma. **SHOULD** prefer `happy-dom` over `jsdom` when the test only needs basic DOM APIs.
- **MUST** use Testing Library `findBy*` (or `waitFor`) for async UI assertions; **SHOULD** pass `{ hidden: true }` to `*ByRole` on large trees.
