# Focused skills/agents sweep — 2026-07-19

## Scope note

This is a **focused** sweep generated as the reuse-evidence base for feature
**F-5** (structural analysis, sprint 0005, roadmap R-9). It deliberately does
**not** run the full per-artefact `skill-review` / `agent-review` pass over all
113 artefacts, nor does it emit the wave-based implementation roadmap that
`spec/claude/skills-agents-sweep/` requires of a major-release gate sweep. It
covers exactly the cross-cutting dimensions F-5 needs — capability overlap,
delimitation-chain concentration, and plugin-boundary signals — measured
deterministically over the on-disk frontmatter. The prior full sweep
(`.audits/skills-agents-sweep/2026-07-01.md`) is untracked and absent from this
worktree; this artefact stands in for the reuse F-5 acceptance-4 requires.

Measurement is reproducible via the scripts recorded in the F-5 analysis
(`.audits/shared-plugin-analysis/2026-07-19.md`).

## Inventory

- **54 agents** — nolte-shared 23, nolte-engineering 29, nolte-media 2.
- **59 skills** — nolte-shared 41, nolte-engineering 15, nolte-media 3.

## Cross-cutting findings

### T1 — Generator/reviewer pairing dominates the nolte-engineering agent budget

The test-tier is built as symmetric generator↔reviewer pairs plus feeder/analyzer
agents: `unit-test-{generator,reviewer}`, `integration-test-{generator,reviewer}`,
`component-test-{generator,reviewer}`, `contract-test-{generator,reviewer}`,
`e2e-test-{generator,reviewer}`, `e2e-result-reviewer`, `test-case-extractor`,
`test-code-adapter`, `test-result-analyzer` — ~15 of nolte-engineering's 29
agents. Each pair carries structurally near-identical `description` prose (same
"generate/review the tier, don't use for X → use the sibling" shape). This is the
single largest concentration of agent-description tokens in the whole inventory
and the highest-yield remediation target for F-7. **Not a boundary defect** — the
pairing is a deliberate test-cycle contract — but a prose-normalisation target.

### T2 — Delimitation-hub repetition inflates descriptions cheaply

A handful of artefacts are named as the "use Y instead" target across the whole
inventory: `quality-gate` (20 inbound delimitation references), `dependency-audit`
(13), `audience-doc-author` (10), `audience-identify` (9), `prose-vale-curator`
(9), `feature-decompose` (9), `workflow-health-triage` (8), `fullstack-developer`
(8). Many agents restate the same delimitation chain verbatim inside their
`description`. Tightening these chains to a single canonical clause each is the
second remediation lever (F-7), and the contract (F-6) should cap chain length.

### T3 — Scanner + companion-skill pattern is consistent, not overlapping

Each read-only scanner pairs with an orchestrating skill under a clean division
(`dependency-audit-scanner`↔`dependency-audit`, `dockerfile-audit-scanner`↔
`dockerfile-audit`, `observability-audit-scanner`↔`observability-audit`,
`kpi-signal-scanner`↔`kpi-derive`, `license-check-scanner`↔`license-check`,
`release-regression-scope-scanner`↔`release-regression-scope`). The delimitation
between scanner (detect) and skill (orchestrate/write) is already crisp — no
merge/retire candidate surfaced. These scanners carry the longest individual
descriptions (dockerfile-audit-scanner 1014c, observability-audit-scanner 995c,
kpi-signal-scanner 974c, release-regression-scope-scanner 955c) — a per-agent
trim target, not a structural one.

### T4 — The plugin/skill-authoring capability is overwhelmingly skill-shaped

The named authoring carve-out candidate — `skill-management`, `skill-review`,
`agent-review`, `skills-agents-sweep`, `skill-agent-catalog-apply`,
`claude-plugin-developer` — is **five skills and one agent**. Only
`claude-plugin-developer` (122 est. tokens) sits in the agent-description budget
this sprint targets; the rest load through the skill mechanism, which is a
different budget. (`cookiecutter-template-author`, 178 t, is the only other
authoring-adjacent agent.) This is the load-bearing input to F-5's boundary
verdict — see the analysis artefact.

### T5 — Agent descriptions are already free of embedded example/commentary blocks

No agent `description` across the three plugins contains `user:` / `assistant:` /
`<commentary>` / `<example>` blocks. PR #329's two-tier trim plus the existing
`check_description` enforcement in `scripts/validate_skills.py` (HTML-tag and
third-person guards) already keep them out. F-7's remediation is therefore
**prose tightening**, not block-stripping — the F-6 contract and F-7 execution
must be framed on that reality, not on the (now-stale) assumption that example
blocks remain to be removed.

## No structural boundary conflicts found

No two agents were found to duplicate the same capability, and no delimitation
edge was found to be circular-without-purpose or contradictory. The inventory's
weight is a function of breadth (many legitimate distinct capabilities), not
redundancy. This directly supports the keep-and-slim reading in F-5's verdict.
