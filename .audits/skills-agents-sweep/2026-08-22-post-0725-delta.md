## Cross-cutting findings

### F1 — `## Operation` singular breaks a MUST (Critical)

`spec/claude/skill-management/en.md:129`: "**MUST** use `## Operations` (plural) as the heading for the operations block; singular `## Operation` is non-conformant."

- `plugins/nolte-engineering/skills/bdd-scenario-generate/SKILL.md` — heading reads `## Operation:` followed by the `generate` verb
- `plugins/nolte-engineering/skills/deployment-chart-manage/SKILL.md` — two headings, `## Operation 1` and `## Operation 2`, carrying the `provision` and `reconcile` verbs

Sixty skills use the conformant plural. Fix: rename the heading to `## Operations` and demote the current headings to numbered `### N.` sub-operations, which the same rule already permits.

### F2 — `resumable: true` missing where the body promises resume (Critical)

`spec/claude/skill-management/en.md:171` makes `resumable: true` a MUST when control flow has more than one approval gate or more than one named phase.

- `skills/cicd-pipeline-design/SKILL.md` — three named operations, `## Resumability` section, `description` ends "Supports resume on re-invocation"
- ~~`skills/backstage-catalog-generate/SKILL.md` — same shape~~ **retracted 2026-08-22.** Its `## Resumability` section documents a deliberate opt-out ("this skill is deliberately **not** `resumable`", with the reason). The heading-presence heuristic that produced this half of the finding was wrong, and setting the flag turned a false positive into a real `resumable-no-persistence` Critical, which is how the error surfaced. The check written for F3 keys on a concrete `.resume/` persistence path instead, so it does not repeat the mistake.

One of 65 skills, not two. Fix: one frontmatter line.

### F3 — the validator sees neither Critical class (Warning)

`scripts/validate_skills.py` at `f46a3ef` reports only description-headroom `Info` entries across all 126 artefacts. Both F1 and F2 are mechanically decidable:

- F1: a `^## Operation[^s]` match in a `SKILL.md`.
- F2: `## Resumability` present and `^resumable:` absent.

This is the finding that makes the other two durable. Without it, the next skill reintroduces them and CI stays green. Fix: two checks in the existing validator, which already owns the description-budget and naming checks.

### F4 — the sanctioned Bash-class list is narrower than practice (Warning)

`spec/claude/agent-management/en.md:96` names exactly three classes beyond the strict git/`gh` set — ephemeral tool runners, network reads, and a bounded single-test re-run — and closes: "A class the section doesn't list stays forbidden."

Four read-only agents name classes outside it:

| Agent | Class named | Raised |
|---|---|---|
| `api-documentation-scanner` | documented export command | 2026-07-25 sweep, finding 3 |
| `capability-maturity-scanner` | report-mode analysis run | 2026-07-25 sweep, finding 3 |
| `error-tracking-audit-scanner` | package-manager metadata read (`pip show`, `npm ls`) | this sweep |
| `observability-audit-scanner` | package-manager metadata read | this sweep |

The 2026-07-25 sweep deferred this to a spec-extension wave. That wave never landed: `agent-management` §Tool access is unchanged and contains zero mentions of a package-manager or export class. The recurrence is the argument — this is the second cycle and the count has doubled.

The classes are legitimate. Reading installed-package metadata is how a scanner separates an SDK that is actually installed and pinned from one merely mentioned in prose, which is the check's entire point. Fix: extend §Tool access with the missing classes and their bounds (metadata reads only; never `install`, `update`, or any resolving write), not narrow four working agents.

### F6 — one-directional delimitation is unruled, and reciprocity would be wrong (Info)

148 of 300 `alternative:` entries name an artefact that does not name the source back. The distribution is the point:

| Named by | Times | Names back |
|---|---:|---|
| `dependency-audit` | 14 | 0 |
| `quality-gate` | 11 | 0 |
| `workflow-health-triage` | 10 | 0 |
| `code-security-reviewer` | 7 | 0 |
| `fullstack-developer` | 7 | 0 |

These are **hubs**, not peers. Requiring `dependency-audit` to name all fourteen artefacts that delimit against it would add roughly a thousand characters to a `description` that is loaded on every routing decision — trading a consistency finding for a measurable routing-budget regression against the 23.1k-token total above.

No rule currently distinguishes the hub case (one-way is correct) from the peer case (mutual delimitation matters). Recorded as `Info` because no spec covers it: per this skill's hard rules an opinion may not be promoted to `Warning`. Fix: a rule in `skill-management` / `agent-management` defining when reciprocity is owed — plausibly "a peer pair whose descriptions address overlapping trigger phrases", which is exactly the boundary-matrix definition this sweep methodology already uses.

Two concrete peer pairs surfaced in phase 1, both recorded in their per-artefact plans rather than restated here: `cicd-pipeline-design ↔ quality-gate-enforcer` (`.audits/skill-review/cicd-pipeline-design.md`, Warning) and `cicd-pipeline-reviewer ↔ quality-gate-enforcer` (`.audits/agent-review/cicd-pipeline-reviewer.md`, Info).

### F7 — section-heading vocabulary is unruled beyond `## Operations` (Info)

| Heading | Majority | Minority |
|---|---|---|
| Preconditions | `## Preconditions` ×33 | `## Precondition` ×3 (`audience-identify`, `cicd-pipeline-design`, `requirements-elicit`) |
| Inputs | `## Inputs` ×18 | `## Inputs — the trigger event` ×1 |

`skill-management` mandates the plural form for `## Operations` only. Nothing covers the rest, so this cannot be promoted above `Info`. Fix: either generalise the plural rule to the standard section set, or accept the variance and stop reporting it. A decision either way retires a recurring observation.

### F8 — six further specs have no skill or agent consumer (Info)

`spec/ansible/playbook-development/`, `spec/ansible/role-development/`, `spec/claude/research-plan-implement/`, `spec/claude/skill-agent-frontmatter/`, `spec/project/elicitation-implementation-separation/`, `spec/project/rest-api-design/`.

These are **not** uniformly phantom-artefact gaps, and reading them as one would be wrong:

- `skill-agent-frontmatter` is consumed by `scripts/validate_skills.py`, a script rather than an artefact — the detection method cannot see it. Not a gap.
- `research-plan-implement` landed on 2026-08-21 (PR #553) with enforcement deliberately deferred in its own Open Questions. Expected, not a gap.
- `elicitation-implementation-separation` governs a repository-level working mode, not a capability. Plausibly no consumer is owed.
- The two `ansible/` specs and `rest-api-design` have no capability in this repository at all. Genuine candidates, each needing its own verdict.

Fix: a per-spec triage verdict in the wave, not a blanket new-artefact decision.
