## 1. Per-plugin agent-description token weight (acceptance-1)

### Measurement method (reproducible)

The metric is the **4-characters-per-token estimate** — `est = len(text) // 4` —
the exact heuristic already used by `check_body_token_estimate` in
`scripts/validate_skills.py` (lines ~427–447). It is applied to the
**concatenation of the `description` frontmatter value of every `*.md` agent file
under each plugin's `agents/` root**:

- `nolte-shared` → `agents/`
- `nolte-engineering` → `plugins/nolte-engineering/agents/`
- `nolte-media` → `plugins/nolte-media/agents/`

Only the `description` field is counted, because that is the field Claude Code
loads into the agent-routing budget on every turn. Reproduce with:

```python
from pathlib import Path
import yaml
def desc(f):
    p = f.read_text().split("---", 2)
    return (yaml.safe_load(p[1]).get("description") or "") if len(p) > 2 else ""
for plugin, root in {
    "nolte-shared": "agents",
    "nolte-engineering": "plugins/nolte-engineering/agents",
    "nolte-media": "plugins/nolte-media/agents",
}.items():
    concat = "".join(desc(f) for f in sorted(Path(root).glob("*.md")))
    print(plugin, len(concat), "chars ->", len(concat) // 4, "est. tokens")
```

## 3. Plugin-boundary decision (acceptance-3)

**Verdict: keep-and-slim `nolte-shared`. Do not split for this sprint's goal.**

### The rule this is bound by

`spec/claude/plugin-scoping/` §"When to split into a separate plugin" permits a
split **only** on a distribution-contract difference — a **runtime/dependency**
requirement or a **consumer-audience** difference — and **never** on topic,
domain, or agent count. The existing three-plugin split obeys this: nolte-media
splits on a runtime/dependency contract (image-gen credentials + `vtracer`),
nolte-engineering on a consumer-audience contract (code repos vs. non-code repos).

### The named candidate, evaluated on its merits

The candidate is extracting the **plugin/skill-authoring** capabilities
(`skill-management`, `skill-review`, `agent-review`, `skills-agents-sweep`,
`skill-agent-catalog-apply`, `claude-plugin-developer`) into a fourth plugin on a
**consumer-audience** contract: most portfolio consumers install nolte-shared for
the delivery lifecycle and never author a plugin or skill.

The consumer-audience *category* is legitimate under the rule — this is **not** a
topic or count split. But two evidence-grounded facts decide it against a split
**for this sprint's objective**:

1. **It barely touches the agent-description budget this sprint targets.** Of the
   six named capabilities, five are **skills** and only `claude-plugin-developer`
   (~122 t) is an agent. Carving the slice out would remove ~122 t — 3.4 % of
   nolte-shared's 3,574 t agent budget, 1.3 % of the 9,227 t total. Even including
   the authoring-adjacent `cookiecutter-template-author` (~178 t) it is ~300 t.
   The routing-budget pressure lives in the test-tier, scanner, deployment, docs,
   and planning-reviewer families (§2) — none of which a authoring split moves.
   A split cannot substitute for the F-7 remediation and F-8 guardrail; those are
   required regardless.
2. **A fourth plugin adds standing cost.** All plugins version in lockstep
   (CLAUDE.md), and the extra plugin's version bump is currently a manual step
   (no marketplace `plugins[].version`). A fourth plugin adds that maintenance
   surface permanently, against a ~122 t one-time agent-budget saving.

### Disposition

Keep `nolte-shared` intact; reclaim the headroom by normalising descriptions
(F-7) and freezing the result with a guardrail (F-8). The authoring carve-out is
**not rejected as an idea** — it remains a valid consumer-audience question for
R-9 / P5, but it must be justified by *skill*-mechanism budget and audience
cleanliness (the skill-list a non-authoring consumer loads), **not** by the
agent-description budget, and weighed against the fourth-plugin cost. Executing
any split is out of scope for this sprint per the sprint's "Out of scope".

No topic-, domain-, or count-based justification is used anywhere in this verdict.
