## Findings

### Warning

- **[portfolio-management §Capability inventory per repository] `nolte/gh-portfolio-ops` and `nolte/pre-commit-hooks` ship no `project/portfolio.yml` and no opt-out marker.**
  Every own (non-fork, non-archived, non-opted-out) repository is a
  Portfolio-Member and MUST either ship a manifest or declare
  `portfolio: excluded` in `CLAUDE.md`. Both are unambiguously
  capability-bearing: `gh-portfolio-ops` = "operational automation over the
  `nolte/*` GitHub portfolio, sibling to gh-plumbing"; `pre-commit-hooks` =
  "a collection of reusable pre-commit hooks for the nolte portfolio, consumed
  remotely". Both carry a normal, non-excluded `CLAUDE.md`. Remediation: per
  repository, run `portfolio-audit` Bootstrap to author a manifest, or add the
  `portfolio: excluded` marker with a one-line rationale. This mirrors the
  gh-plumbing/taskfiles manifest gap from 2026-06-02, now closed.

### Suggestion

- **[tech-stack §Per-repository tech-stack block] 11 capability-bearing members carry no `tech_stack:` block.**
  Only 4 of 15 manifests (`claude-shared`, `blog`, `vale-style`, `workstation`)
  declare a `tech_stack:` block. Members with a genuine repo-specific stack
  delta — `kamerplanter`, `kamerplanter-ha`, `reachy-mini-app`,
  `reachy-mini-mcp`, `cookiecutter-gh-project`, `terraform-github-bootstrap` —
  would benefit from running `tech-stack-capture`. The missing block is **not**
  an error (they inherit the portfolio baseline by construction), only a
  completeness opportunity. Low priority — capability inventory is unaffected.

- **[portfolio-management §Decision documentation] The Reachy-Mini cluster carries no intra-cluster `peers:` edges.**
  `reachy-mini-app`, `reachy-mini-mcp`, `claude-reachy-mini`, and
  `ansible-reachy-mini-bootstrap` form a coherent cluster (behavior app,
  MCP server, Claude Code plugin, and Ansible provisioning for the same
  device) but declare no `peers:` references among one another. This is not a
  duplicate; adding the `<repo>:<capability>` cross-references would let the
  rendered inventory draw the cluster relationship. Operator to confirm scope
  and add the peer edges if desired.
